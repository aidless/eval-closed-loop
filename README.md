# eval-closed-loop

把「跑一次公开 benchmark」变成一条**可复现、带置信区间、能阻断、能归因**的评测闭环：

```
benchmark runner → 置信区间 → 回归门禁 → judge κ 校准 → 一页可点开的报告
```

本机真实跑通，不是示例数据。数据：GSM8K `openai/gsm8k` `test`；主结果是**全量 1,319 题**，
另保留分层 n=300（中间档）与旧随机 n=60（最小闭环）作对照。
模型：本地 ollama 的 `qwen2.5:1.5b`、`qwen2.5:0.5b`，第三裁判 `qwen2.5:3b`；全程离线（除首次拉取模型）。

**这个仓能证明什么**：一条从 runner 到门禁再到报告的闭环在真实 GSM8K 数据上跑通，主结果 1,319 题的
准确率、Wilson/bootstrap 区间、judge κ 与门禁判决都能从落盘结果复算。

**这个仓不能证明什么**：不能外推到其他模型或数据集，也不是排行榜结论——只覆盖 GSM8K、两个小尺寸
被测模型（qwen2.5:1.5b / 0.5b）外加一个 3B 裁判，三档抽样互为对照、不可混算。

## 样本量-宽度收缩（实测，不是推算）

同一张图（`reports/width_curve.png`，也内嵌进 `reports/index.html`）：三档实测 Wilson / bootstrap 宽度 + 各 run 用全量 p 代入的 √n 理论线。

| run | n=60 W 宽 | n=300 W 宽 | n=1,319 W 宽 | 60→300 收缩 | 300→1319 收缩 | √n 理论值（60 / 300 / 1319） |
|---|---|---|---|---|---|---|
| A-cot | 0.226 | 0.106 | 0.050 | -53% | -52% | 0.236 / 0.106 / 0.050 |
| A-short | 0.172 | 0.061 | 0.029 | -65% | -52% | 0.135 / 0.060 / 0.029 |
| B-cot | 0.242 | 0.111 | 0.054 | -54% | -52% | 0.251 / 0.112 / 0.053 |

- **扩样本买到什么**：n 扩大 5.0 倍（60→300），宽度砍掉一半（-53%～-65%）；再扩大 4.4 倍（300→全量），宽度再砍一半（-52%～-53%）。
  实测收缩率与 1/√n 理论几乎重合，说明「样本量换精度」这条路在本任务上是有效的，且**没有白跑的部分**。
- **目标宽度 ≤0.05 的真实结论（全量实测）**：
  - A-short **0.029** 达标（p 低，本来就好压）。
  - A-cot **0.0503**，比目标高 0.0003——p≈0.68 时 n=1,319 的 Wilson 理论下限就是 0.0503，**这已经是全测试集能给到的最窄区间**；
    要严格 ≤0.05 需要约 1,338 题（超出 test 全量，**未验证**）。
  - B-cot **0.0535** 未达标；按 p≈0.44 反解需约 1,513 题，**超出全量，未验证**。
  - 结论：**在 GSM8K test 全量内，A-cot/B-cot 无法把宽度压到 0.05 以下**；继续加样本只能换数据集，不是加题能解决的事。

## Judge κ（人工标注 n=150，steps 桶 37/76/37）

人工标注从 60 条扩到 150 条，四个主裁判全部重算；CI 为**按标注成对 bootstrap**（10,000 次，seed=20261105）。
「达 ±0.05 所需 n」按 CI 宽度 ∝ 1/√n 反解。

| judge | 配置 | n | 解析率 | po | pe | Cohen's κ | κ 95% CI | CI 宽 | 达 ±0.05 所需 n |
|---|---|---|---|---|---|---|---|---|---|
| rule（数字精确匹配） | — | 150 | 1.000 | 0.993 | 0.567 | **0.985** | [0.950, 1.000] | 0.050 | —（CI 触顶截断，不作反解） |
| qwen2.5:0.5b | raw | 150 | 1.000 | 0.627 | 0.460 | **0.308** | [0.189, 0.434] | 0.245 | 901 |
| qwen2.5:1.5b | raw | 149 | 0.993 | 0.866 | 0.625 | **0.643** | [0.502, 0.771] | 0.269 | 1,078 |
| qwen2.5:3b | raw | 150 | 1.000 | 0.920 | 0.540 | **0.826** | [0.726, 0.913] | 0.188 | 528 |

**已知结论对照（保留，不重跑）**：few-shot / rubric 变体仍只覆盖 60 条子批次，表现为标签塌缩，不作为可用配置：

| judge | 配置 | n | κ | κ 95% CI |
|---|---|---|---|---|
| qwen2.5:1.5b | fewshot（3 锚点） | 60 | **-0.000** | [-0.000, 0.000] |
| qwen2.5:1.5b | rubric（C1–C4） | 60 | 0.076 | [0.000, 0.253] |
| qwen2.5:3b | fewshot | 60 | 0.124 | [0.047, 0.235] |
| qwen2.5:3b | rubric | 60 | 0.124 | [0.046, 0.235] |

分难度桶 κ（`n` 为该桶标注条数）：

| bucket | n | rule | 0.5b raw | 1.5b raw | 3b raw |
|---|---|---|---|---|---|
| steps_1_2 | 37 | 0.934 | 0.105 | 0.593 | 0.704 |
| steps_3_4 | 76 | 1.000 | 0.384 | 0.578 | 0.829 |
| steps_5_plus | 37 | 1.000 | 0.354 | 0.800 | 0.942 |

- **为什么 rule κ 不是 1.000**：150 条里有 1 条人工与判分器不一致（`gsm8k-test-1163`：`\boxed{12}` 与金标一致，
  但判分器把正文里的 `2 days` 取成了 `2.0`）。这是**判分器的提取误差**，不是人工标错；已写进报告的分歧表。
- **κ 扩到 150 换来了什么**：3b raw 在 n=150 下的 CI 是 [0.726, 0.913]（宽 0.188）；
  要把 κ 的 ±0.05 压住，3b raw 需约 **528 条**，1.5b raw 约 **1,078 条**，0.5b 约 **901 条**（均为反解，**未验证**）。
- **选型结论不变**：本机 3B 以下模型加 few-shot/rubric 会塌缩；**raw prompt 最优**，3b raw (0.826) > 1.5b raw (0.643) ≫ 0.5b (0.308，不可用于门禁）。

## 稳定性（A-cot 全量跑两次）

A-cot 全量跑两遍（同样 greedy：temperature=0、seed=42、num_predict=512、同一 prompt），逐题比对 `output` 全字符串：

| 指标 | 结果 |
|---|---|
| 比对题数 | 1,319 |
| 输出完全一致 | 1,300（98.6%） |
| 输出不一致 | **19（1.44%）** |
| 正确性翻转 | **2**（1→0：`gsm8k-test-260`；0→1：`gsm8k-test-479`），净变化 0 |
| 两遍准确率 | 897/1,319（0.680）→ 897/1,319（0.680） |

**结论：greedy 在本机不是逐字节确定，但点估计稳定。** 19 处差异的首个不同字符位置中位数在第 147 字符
（3 处从第 0 字符就不同，长 CoT 在中途分叉），说明是同一题的不同推理路径，不是格式化抖动。

**归因（不是 seed / 采样参数）**：抽 20 题（10 题两遍有差异 + 10 题两遍无差异），用**完全相同的 payload**
各请求 3 次：**13/20 题在同一批请求里就出现不一致**（连 10 题「两遍无差异」组里也有 4 题在 3 次重复中分叉）。
参数已固定却仍分歧 → 原因是 **GPU 推理的浮点归约 / 并行执行不保证逐位可复现**；temperature=0 的 argmax
在近似并列处被尾数差异翻转，再被自回归放大。证据：`reports/stability_repeat.json`。

**能不能用单次结果对外报价**：能报**分数**——单次波动的量级是 ±2/1,319（±0.15 pp），远小于区间半宽（≈2.5 pp）；
不能报**逐题输出**，逐题复现需要 CPU 路径或固定执行环境（本仓库未验证 CPU 全量的逐题一致性，**未验证**）。

## 成本（全量实测，不外推）

token 取自 ollama 返回的 `prompt_eval_count` / `eval_count`；墙钟为单题请求耗时（含 prefill+decode），
「整轮实测墙钟」= 启动到末次落盘（含模型加载与进程开销）。**本机 GPU 同时有另一训练进程占用约 3.3 GB 显存，耗时含该并发影响。**

| run | n | prompt tokens/题 | 生成 tokens/题 | 合计/题 | 墙钟/题 | Σ单题墙钟 | 整轮实测墙钟 | 实测总 token |
|---|---|---|---|---|---|---|---|---|
| A-cot | 1,319 | 113 | 283 | 396 | 3,562 ms | 78.3 min | **78.4 min** | 523,005 |
| A-short | 1,319 | 104 | 3 | 108 | 89 ms | 2.0 min | **2.0 min** | 142,004 |
| B-cot | 1,319 | 113 | 308 | 421 | 1,432 ms | 31.5 min | **31.5 min** | 555,311 |

全量三 run 合计：**约 112 分钟墙钟、1.22 M tokens**（本机实测；B-cot 用 0.5b，单题更快但答案更长）。

执行方式：三个 run **串行**，不并发。实测并发时 0.5b 会被挤到 CPU（`ollama ps` 显示 CPU/GPU 混合，单题从 1.4s 掉到 ~20s），
所以 B-cot 第一轮的 6 条被作废、从头重跑至 1,319；A-short 也有一次并发尝试被中止，最终为独立完整跑。**最终三份结果都是干净的单跑。**

CPU 侧只做**抽样实测**（`num_gpu=0`，n=100，首题预热丢弃），**不做全量外推**：

| model | 抽样题数 | prompt tokens/题 | 生成 tokens/题 | 墙钟/题 | 抽样总时长 |
|---|---|---|---|---|---|
| qwen2.5:1.5b | 100 | 112 | 283 | 12,173 ms | 20.3 min |
| qwen2.5:0.5b | 100 | 112 | 305 | 5,472 ms | 9.1 min |

**CPU vs GPU（仅这 100 题抽样，不是全量）**：1.5b 慢 **3.4×**（12.2s vs 3.56s/题），0.5b 慢 **3.8×**（5.47s vs 1.43s/题）。
按比例换算全量只是算术，**未实测，不作外推**。

```bash
make repro N=1319  # 全量（分层 1,319 题；从零约 112 分钟串行生成，已有结果时秒级重算；断点续跑）

```

报告与 `summary.json` 始终覆盖为最新一轮（当前为全量档）。

产物：`reports/index.html`（一页报告，含内嵌曲线图）、`reports/width_curve.png` / `.json`、`reports/summary.json`、

## 门禁规则（`--report-only` 可只出报告不改退出码）

| gate | 规则 | 不通过时 |
|---|---|---|
| G1-absolute | Wilson 下限 ≥ 0.10（弱本地模型场景的绝对地板） | FAIL |
| G2-regression | 配对 delta ≤ -0.05 且 bootstrap CI 上限 < 0 | BLOCK |
| G6-evidence | 候选与基线题目集合完全一致 | INCOMPLETE |
| G5-power | n ≥ 50 且 CI 宽度 ≤ 0.25 | REVIEW |

优先级 `BLOCK > INCOMPLETE > FAIL > REVIEW > PASS`：删证据或删题不能把 BLOCK 降级。

## 局限与未验证项

- **两个主模型都是 1.5B 以下的本地小模型**，没有 API 强模型对比；`qwen2.5:3b` 已实际下载并作为第三裁判跑通。
- **结论只覆盖本机这批模型与 GSM8K test 全量**：不再有「扩样本」余地（n 已是 test 上限），也不外推到其他模型/benchmark。
  对外引用必须带 n 与区间；A-cot 0.0503 / B-cot 0.0535 均未严格达到 0.05。
- **CPU 只做了 n=100 抽样实测**，没有整轮 CPU 跑完 1,319 题；任何「CPU 跑全量要多久」都是外推，标未验证。
- **judge κ 只对本次裁判有效**：换裁判模型必须重新标注/校准；judge 只看最终答案，不评价推理过程，
  「过程错但答案对」会被判为对。n=150 下分桶 κ 每桶 37/76/37 条，桶内 κ 仍有波动。
- **成本受同机并发影响**：GPU 上另有训练进程占约 3.3 GB 显存；同一命令在独占机器上应该更快，本表不当作基准。
- **G1 的 0.10 地板是弱模型场景的设定值**，不是通用阈值；强模型应上调。
